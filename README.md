# Пресс-мониторинг

Учёт материалов пресс-службы Четвёртого кассационного суда общей юрисдикции и материалов других ресурсов,
сделанных на их основе, с отчётом за период.

- **Материал**: заголовок, дата, один или несколько видов (новость, статья, аналитика…), одна или несколько ссылок
  (сайт, Telegram, ВК, MAX — тексты на разных площадках могут отличаться).
- **Сбор собственных публикаций**: сайт суда (раздел «Пресс-служба» на sudrf.ru), Telegram-канал
  (публичная веб-версия t.me/s/…), группа ВКонтакте (API, нужен бесплатный сервисный ключ).
  Версии одного материала на разных площадках склеиваются автоматически: по ссылке «Подробнее» на сайт,
  по общей ссылке на первоисточник и по почти одинаковому заголовку. Ошибки исправляются кнопкой «Объединить».
- **Мониторинг сторонних ресурсов**: RSS-ленты, HTML-страницы со списком публикаций и Telegram-каналы.
  Новые публикации сравниваются с нашими материалами; похожие и упоминающие суд попадают на страницу «Проверка»,
  где человек подтверждает или отклоняет связь.
- **Отчёт** за период на экране и в Excel.

Канал MAX не отдаёт посты без входа в аккаунт, поэтому ссылки на MAX пока добавляются вручную.

## Как ищутся перепечатки

1. Публикация ссылается на наш материал (сайт суда, пост канала) — совпадение наверняка.
2. Иначе сравниваются тексты: слова приводятся к основе («суда», «суду» → «суд»), каждому слову даётся вес
   по редкости — она считается по нашим материалам и по всему потоку публикаций отслеживаемых СМИ. Поэтому
   «суд», «кассационный», «Краснодар» почти ничего не весят, а фамилии, названия, суммы и номера дел — много.
   Похожесть — доля общего «веса» двух текстов (взвешенный коэффициент Дайса). Кандидатом считается публикация
   с похожестью от 0,35 (`Monitoring:CandidateThreshold`): на реальных примерах перепечатки получают 0,46–0,74, посторонние публикации — не выше 0,27.
3. Публикации с ключевыми фразами («Четвертый кассационный суд», «4КСОЮ»…) или со ссылкой на наш ресурс,
   для которых пара не нашлась, попадают в «Упоминания».
4. Наши перепечатки чужих материалов (новости ВС РФ, Совета судей) в сравнении не участвуют — публикации СМИ
   о них сделаны не на основе наших материалов. Перепечатка определяется по «Источник:» на сайте, пересылке
   в Telegram и по ссылке на источник из списка «Источники перепечаток» (страница «Сбор»).

Чтобы не нагружать сайты, у RSS-лент полный текст загружается только для публикаций, отобранных по заголовку
и анонсу; для небольших региональных изданий в настройках ресурса можно включить загрузку каждой публикации.

## Как добавить ресурс для мониторинга

Страница «Ресурсы» → «Добавить ресурс». Снимите галочку «Собственный ресурс», заполните название, адрес
и префикс ссылок (домен сайта, например `kubnews.ru`, или `t.me/имя_канала/` для канала), затем выберите способ
мониторинга. Какой способ выбрать — по таблице:

| Ресурс | Способ | Что указать в «Источник» |
|---|---|---|
| Telegram-канал | Telegram — публичный канал | имя канала: `rapsinewsru` (из адреса `t.me/rapsinewsru`) |
| Группа ВКонтакте | ВКонтакте — стена сообщества | короткое имя (`4kassud`) или id (`-217666653`); нужен ключ ВК |
| Сайт, у которого есть RSS | RSS-лента | адрес RSS-файла (не главной страницы!) |
| Сайт без RSS | HTML-страница со списком публикаций | адрес страницы со списком новостей + CSS-селектор |

**RSS лучше HTML-страницы**: это файл, специально сделанный для программ, — с точными датами и анонсами,
и он не ломается, когда сайт меняет дизайн. Поэтому сначала ищите RSS и только если его нет — используйте HTML.

### Что такое RSS и чем он отличается от «ленты новостей» на сайте

«Лента новостей» на странице сайта (как на kuban.bfm.ru) — это часть обычной веб-страницы для людей: заголовки,
картинки, оформление. RSS — отдельный служебный файл по своему адресу, в котором тот же список новостей записан
в машиночитаемом виде. Если открыть его в браузере, вместо привычной страницы будет текст с тегами
`<rss>`, `<item>`, `<title>`, `<link>`, `<pubDate>` (или браузер предложит скачать файл). Наличие ленты на странице
ничего не говорит о наличии RSS: у kuban.bfm.ru лента на главной есть, а RSS-файла нет.

### Как найти RSS сайта

1. Поищите на сайте значок RSS (оранжевый квадрат с дугами) или слово «RSS» — чаще всего в подвале сайта
   или на странице «RSS-ленты» (например, у «Коммерсанта» — kommersant.ru/rss-list).
2. Откройте код главной страницы (Ctrl+U) и поищите (Ctrl+F) `rss` — иногда адрес указан в строке вида
   `<link rel="alternate" type="application/rss+xml" href="…">`.
3. Попробуйте типичные адреса, дописав их к адресу сайта: `/rss`, `/rss/`, `/rss.xml`, `/feed`, `/feed/`,
   `/rss/news`, `/export/rss2/index.xml`.
4. **Проверьте, что открылся именно RSS**, а не главная страница: многие сайты на несуществующий адрес
   показывают главную. В RSS должны быть видны `<item>` и `<pubDate>`.
5. Если RSS несколько (по рубрикам или регионам), выбирайте самый узкий подходящий: региональную или судебную
   рубрику, а не общую ленту всего издания — в ней меньше лишнего, и новости не успевают из неё «вытечь»
   между проверками.

Адреса уже найденных лент: rapsinews.ru/export/rss2/index.xml, rg.ru/xml/index.xml,
kommersant.ru/RSS/news.xml, kubnews.ru/rss/.

### Если RSS нет: HTML-страница и CSS-селектор

Укажите адрес страницы, где новости выводятся списком (главная или раздел «Новости»), и CSS-селектор —
правило, по которому приложение отличит ссылки на новости от остальных ссылок (меню, реклама, соцсети).

Как подобрать селектор:

1. Откройте страницу со списком, щёлкните правой кнопкой по заголовку любой новости → «Просмотреть код»
   (или «Исследовать элемент»).
2. Посмотрите адрес ссылки (`href="…"`) у нескольких новостей и найдите общую часть.
   Например, у kuban.bfm.ru все новости имеют вид `/news/63249`, `/news/63286` — общая часть `/news/`.
3. Селектор: `a[href*='/news/']` — «ссылки, в адресе которых есть /news/». Аналогично `a[href*='/article/']`,
   `a[href*='/2026/']` и т.п.

Поле можно оставить пустым — тогда берутся все ссылки на страницы того же сайта, но в очередь попадёт больше лишнего.
Для небольших изданий включите «Загружать полный текст каждой публикации»: в HTML-списке нет анонсов,
и без полного текста сравнивать будет почти не с чем.

### Проверка после добавления

На странице «Сбор» нажмите «Проверить сейчас» у нового ресурса. В колонке «Последняя проверка» должно
появиться «Новых публикаций: N» с N больше нуля. Если там ошибка или ноль:

- «Сайт не ответил вовремя» — сайт недоступен с сервера (возможно, нужен прокси);
- ошибка разбора или 0 публикаций у RSS — скорее всего, указан адрес не RSS-файла, а обычной страницы;
- 0 публикаций у HTML-страницы — селектор не подходит, проверьте общую часть адресов ещё раз.

## Стек

.NET 10, ASP.NET Core + Blazor Server, EF Core + PostgreSQL, AngleSharp, ClosedXML. Развёртывание — Docker Compose.

```
src/Press.Web/
  Domain/        сущности
  Data/          DbContext, миграции, начальные данные
  Collectors/    сборщики: sudrf.ru, Telegram, ВКонтакте, RSS, HTML-список
  Services/      склейка публикаций, мониторинг и сопоставление, материалы, отчёт, пользователи
  Components/    интерфейс (Blazor)
tests/Press.Tests/  тесты (в т.ч. разбор сохранённых копий реальных страниц и лент)
```

## Развёртывание (Docker)

На сервере нужны Docker и Docker Compose (Linux или Windows Server с Docker).

```
cp .env.example .env        # задать пароли, при необходимости прокси и ключ ВК
docker compose up -d --build
```

Приложение: `http://сервер:5080`, вход — `ADMIN_LOGIN` / `ADMIN_PASSWORD` из `.env`
(используются только при создании пустой базы; потом пароль меняется на странице «Пользователи»).

При запуске приложение само применяет миграции базы данных. При первом запуске загружается архив
собственных публикаций за 60 дней, затем проверяются отслеживаемые ресурсы — это занимает несколько минут.

Обновление: `git pull && docker compose up -d --build`.

### Прокси

- Для работы приложения — `PROXY_URL` (и при необходимости `PROXY_USER`/`PROXY_PASSWORD`) в `.env`.
- Для сборки образа (загрузка .NET-пакетов) Docker использует прокси из своих настроек
  (`~/.docker/config.json`, раздел `proxies`). Если сервер совсем без интернета — соберите образ на другой машине,
  перенесите `docker save press-monitoring:latest | gzip > press.tar.gz` и загрузите `docker load < press.tar.gz`.

### Резервное копирование

Все данные (включая ключи шифрования cookie) хранятся в PostgreSQL:

```
docker compose exec db pg_dump -U press press > backup.sql
docker compose exec -T db psql -U press press < backup.sql     # восстановление в пустую базу
```

### Ключ ВКонтакте

1. Войти на https://id.vk.com/about/business/go и создать приложение (бесплатно).
2. В настройках приложения скопировать «Сервисный ключ доступа» в `VK_SERVICE_TOKEN` в `.env`.
3. `docker compose up -d`, затем на странице «Ресурсы → Группа ВКонтакте» включить «Проверять по расписанию».

## Разработка

Нужны .NET 10 SDK и PostgreSQL. Проще всего поднять только базу из compose:

```
docker compose up -d db
dotnet run --project src/Press.Web
```

Строка подключения по умолчанию — `Host=localhost;Port=5432;Database=press;Username=press;Password=press`
(`ConnectionStrings:Default` в `appsettings.json`); пароль должен совпадать с `POSTGRES_PASSWORD`, либо задайте
строку переменной окружения `ConnectionStrings__Default`. В режиме Development сбор по расписанию выключен —
запускайте его на странице «Сбор».

Тесты (база для них не нужна — используется SQLite в памяти): `dotnet test`.

### Миграции

Схема базы меняется только через миграции EF Core:

```
dotnet tool restore
dotnet ef migrations add <Название> -p src/Press.Web -o Data/Migrations
```

Миграции применяются автоматически при запуске приложения. SQL-скрипт для ручного применения:
`dotnet ef migrations script --idempotent -p src/Press.Web -o migrate.sql`.

## Настройки

`src/Press.Web/appsettings.json`, любую можно переопределить переменной окружения (`Раздел__Параметр`):

| Параметр | Назначение |
|---|---|
| `ConnectionStrings:Default` | строка подключения к PostgreSQL |
| `Auth:InitialAdmin` | логин и пароль первого пользователя |
| `Collection:Enabled` | сбор и мониторинг по расписанию |
| `Http:Proxy:*` | прокси для выхода в интернет |
| `Vk:ServiceToken` | сервисный ключ ВКонтакте |
| `Monitoring:LookbackDays` | с нашими материалами за сколько дней сравнивать (60) |
| `Monitoring:CandidateThreshold` | порог похожести для «Похожие на наши» (0,35) |
| `Monitoring:PrefilterThreshold` | порог отбора по анонсу для загрузки полного текста (0,3) |

Ключевые фразы и источники перепечаток редактируются на странице «Сбор».
