# CLAUDE.md

Приложение пресс-службы Четвёртого кассационного суда общей юрисдикции: учёт собственных материалов и поиск
материалов других ресурсов, сделанных на их основе, с отчётом. Пользователи — 2 человека из пресс-службы.
Общее описание, развёртывание и настройки — в README.md.

## Язык

Интерфейс, комментарии в коде, сообщения коммитов и общение с пользователем — на русском.

## Ограничения от заказчика

- Только бесплатные источники и сервисы: никаких платных API (поиск Яндекса, TGStat, LLM и т.п.).
- Стек: C# / .NET 10, ASP.NET Core + Blazor Server, EF Core + PostgreSQL, Docker Compose.
- Найденные перепечатки подтверждает человек: точность важнее полноты, но очередь не должна быть замусорена.

## Команды

```
dotnet build
dotnet test                                   # база не нужна: тесты на SQLite в памяти
dotnet tool restore
dotnet ef migrations add <Название> -p src/Press.Web -o Data/Migrations
docker compose up -d --build                  # прод: PostgreSQL + приложение, настройки в .env
```

## Устройство

- `Collectors/` — сборщики (`ICollector`): `SudrfPressCollector` (sudrf.ru, windows-1251), `TelegramPublicCollector`
  (t.me/s/канал), `VkWallCollector` (API ВК, нужен сервисный ключ), `RssCollector`, `HtmlListCollector`.
- `CollectionService` — для собственных ресурсов склеивает версии одного материала (ссылка «Подробнее»,
  общая ссылка на первоисточник, похожий заголовок); для сторонних передаёт работу `MonitoringService`.
- `MonitoringService` + `Matching.cs` — поиск перепечаток: idf-взвешенный коэффициент Дайса по основам слов,
  ключевые фразы, ссылки на наши ресурсы. Результат — `MonitoredItem` в очереди «Проверка».
- `UrlKey` — канонический ключ ссылки (http/https, www, m., vk.ru→vk.com, AMP, utm, `&amp;amp;` из Telegram).
  Все сравнения ссылок идут по нему.
- Время хранится в UTC, показывается в МСК через `Msk` (фиксированное +3; часовые пояса ОС не используются).

## Подводные камни (уже наступали)

- **Dockerfile:** не публиковать с `--no-restore`. Восстановление идёт, когда в папке только `.csproj`, и SDK
  не подключает пакет со скриптами Blazor — в образе нет `_framework/blazor.web.js`, интерфейс не реагирует.
- **Таймауты HTTP** приходят как `TaskCanceledException`. Ловить ошибки сборщиков через
  `catch (...) when (!ct.IsCancellationRequested)`, а не `when (ex is not OperationCanceledException)` — иначе
  таймаут одного сайта роняет планировщик и весь хост.
- **Пороги сопоставления** (`Monitoring:*` в appsettings.json) откалиброваны 2026-10-10 на шести реальных
  перепечатках одного дела: перепечатки 0,46–0,74, посторонние публикации ≤ 0,27, порог 0,35. Менять только
  после проверки на реальных примерах и полном прогоне мониторинга (смотреть распределение `Score`).
- **Выделение текста статьи** (`PageMetadataService.MainParagraphs`): абзацы группируются по месту в разметке.
  У «Коммерсанта» абзацы — `div`, а полный текст есть в meta description; у BFM боковая лента — `<a><p>`.
- Наши перепечатки чужих новостей (ВС РФ, Совет судей) помечаются `IsRepost` и в сопоставлении не участвуют.
- `dotnet run` в режиме Production не раздаёт файлы фреймворка (404/500 на `blazor.web.js`) — для проверки
  прод-поведения публиковать (`dotnet publish`) и запускать сборку, лучше повторяя шаги Dockerfile.
- В `.gitignore` не добавлять правила вида `**/data/`: на Windows они совпадают с папкой `Data/` (DbContext, миграции).

## Проверка

- Парсеры тестируются на сохранённых копиях реальных страниц (`tests/Press.Tests/Samples`, хранятся байт-в-байт).
  Сторонние статьи целиком в репозиторий не класть — для них синтетическая разметка в тестах.
- Интерактивность Blazor (фильтры, кнопки) тестами не покрыта; проверять в браузере, например Playwright
  с системным Edge (`channel="msedge"`), на опубликованной сборке.
